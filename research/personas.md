# AI 페르소나 인터뷰 (가설 확장용)

> ⚠️ **AI가 시뮬레이션한 인터뷰입니다. 기획서에 "사용자 인터뷰 결과"로 인용하지 마세요.**
> 쓰는 목적은 세 가지입니다. ① 놓친 사용자군 찾기 ② 예상 반론 미리 모으기 ③ 실제 인터뷰 질문 다듬기.
> 각 페르소나에게 후보 A~D를 한 줄씩 설명하고 반응을 받았습니다.

| # | 페르소나 | 차량 · 운전 패턴 |
|---|---|---|
| P1 | 42세 제약 영업사원 (개인 차량, 자가운전보조금 + 실비) | 그랜저, 하루 거래처 4~6곳, 월 2,500km |
| P2 | 38세 인테리어 개인사업자 (복식부기) | 팰리세이드, 현장 이동 + 자재 구매 |
| P3 | 51세 중소기업 총무팀장 (법인차 12대 관리) | 공용 법인차, 운전자 여러 명 |
| P4 | 34세 IT 스타트업 대표 (법인 리스 EV) | 아이오닉, 투자사 미팅 + 출퇴근 혼용 |
| P5 | 45세 독일 주재원 (회사차, Fahrtenbuch 대상) | 유럽 출시 EV 가정 |
| P6 | 36세 맞벌이 부모 (EV, 주말 장거리) | 아이 둘, 휴게소 충전 |
| P7 | 29세 차를 아끼는 직장인 | 아반떼, 3년 뒤 매각 예정 |
| P8 | 47세 세무사 (고객 사업자 기장 대행) | 사용자가 아닌 **구매 영향자** |

## 반응 요약

### P1 영업사원 — A에 강하게 반응
> "월말마다 카드 내역 보면서 어디 갔는지 기억해 내는 게 제일 싫어요. 기록을 몰아서 쓰니까 거리도 대충 맞추고요."
> "앱은 깔았다가 배터리 때문에 지웠어요. 차에 타면 알아서 되면 좋죠."
- 반론: "**회사가 내 위치를 다 보는 건 싫다.** 퇴근길까지 찍히면 안 돼요."
- 인사이트 → **업무/개인 운행 구분은 운전자가 결정하고, 개인 운행은 위치를 저장하지 않는다**(거리만 남기기)는 원칙이 필요.

### P2 개인사업자 — A에 반응, 지불 의향 있음
> "세무사가 운행기록부를 쓰라는데 솔직히 안 써요. 1,500만원 넘는 줄도 몰랐어요."
- 반론: "기록은 되는데 결국 **세무사한테 넘기는 게 일**이에요. 엑셀로 바로 나와야 해요."
- 인사이트 → **국세청 서식 그대로 내보내기 + 세무사 공유 링크**가 핵심 기능.

### P3 총무팀장 — A의 B2B 버전에 가장 강하게 반응
> "공용차는 누가 몇 km 탔는지가 제일 골치예요. 키 대장 쓰라고 해도 안 써요."
- 인사이트 → **"누가 운전했는지" 자동 식별**이 필요. 차량 데이터 중 **시트 메모리·운전석 위치·Pleos 프로필**로 운전자를 추정할 수 있음 → 폰 앱으로는 불가능한 차량 고유 기능.
- 지불 주체: 회사(차량당 월 과금). 기존 법인카드·경비 시스템 연동을 원함.

### P4 스타트업 대표 (EV) — A + 전비 연동에 반응
> "EV는 주유 영수증이 없어서 업무용 전기료를 어떻게 나누는지 애매해요."
- 인사이트 → **EV는 주유 영수증 대신 kWh × 전비로 업무 주행 에너지 비용을 계산**하는 기능이 필요. EvBattery 효율 API와 맞물리고, 현대차 EV 전략에도 맞음.

### P5 독일 주재원 — A의 글로벌 근거
> "Fahrtenbuch는 한 줄만 빠져도 전체가 무효예요. 수정하면 흔적이 남아야 하고요."
- 인사이트 → **수정 이력이 남는(append-only) 기록 구조**를 처음부터 설계하면 독일 요건까지 대응할 수 있음 = 글로벌 확장 스토리.

### P6 맞벌이 부모 — C·D에 미지근
> "충전 기다릴 땐 애들 화장실 가고 간식 사요. 차에서 쉴 일은 별로 없어요."
> "애들은 태블릿 보죠. 차 화면 게임은 운전석 쪽이라 위험해 보여요."
- 인사이트 → C의 '라운지' 가정이 약하다는 데스크 리서치 결과와 일치. D는 정책 리스크에 더해 수요도 약함.

### P7 차를 아끼는 직장인 — B에 관심, 지불 의향은 낮음
> "기록해 두면 좋긴 한데 돈 내고 쓰진 않을 것 같아요. 정비는 블루핸즈 기록이 남잖아요."
- 인사이트 → B는 사업성(지불 주체)이 약함.

### P8 세무사 — A의 구매 영향자
> "고객들이 운행기록부를 제출해도 사후에 만든 티가 나요. 계기판 거리랑 안 맞으니까요."
- 인사이트 → **"차량 계기판 데이터로 생성된 기록"이라는 신뢰성 자체가 가치**. 세무사 채널(기장 고객에게 추천)로 확산하는 그림이 가능.

## 종합 (가설 업데이트)
1. 후보 A가 가장 많은 사용자군(P1·P2·P3·P4·P5·P8)에서 반응을 얻었고, 지불 주체(회사·사업자)도 분명함.
2. A를 이기는 아이디어로 만드는 차별 요소 4가지:
   - **계기판 기반 신뢰성**: GPS 추정이 아닌 실제 주행거리
   - **운전자 자동 식별**: 공용 법인차에서 시트·프로필로 운전자를 추정
   - **EV 에너지 비용 자동 계산**: 전비 × kWh
   - **수정 이력이 남는 기록**: 독일 Fahrtenbuch 수준
3. 반드시 다룰 반론: **위치 프라이버시**(개인 운행은 거리만 저장), **입력 귀찮음**(주차 시 원탭 프리셋 + Gleo 음성), **세무사·회사로 넘기는 출력**.
4. C·D는 우선순위를 내림. B는 A 안에 "주행거리 기반 정비 알림" 정도로 흡수할 수 있음.
