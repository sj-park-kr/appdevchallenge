# B. Pleos Connect 앱 설계 가이드 (vehicle-app-planning-guide) 정리

> 원문: `research/raw/pleos-docs/pleos-only/vehicle-app-planning-guide/` 10개 파일 (수집 2026-10-23).
> 원문 표는 HTML 평탄화로 열과 플래그가 섞여 있어, 표 값은 원문 순서 그대로 옮겼다. 열별 플래그 대응이 불명확한 부분은 "원문 플래그"로 표기했다.

## 0. 설계 가이드 개요 (intro.md)
- 모바일 앱을 Pleos Connect 앱으로 전환하거나 처음부터 설계할 때 고려할 사항을 안내한다.
- 본문은 "주행 안전을 고려한 설계" 한 줄 소개뿐이다. 나머지 수치·규칙은 하위 문서에 있다.

## 1. 지역별 주행 규제 정책 (driving-restiction-policy.md)
- `CarUxRestrictions` 연동 방법은 "주행 규제 개발 가이드"를 참조한다 (해당 문서는 우리 폴더에 없음).
- 플랫폼 버전과 양산 차량에 따라 주행 규제 정책이 다를 수 있다.
- 주행 규제는 차량의 **속도·기어·브레이크 등 하드웨어 신호**와 지역별 안전 규정에 따라 적용된다. 구체적인 속도·기어 기준값은 **문서에 없음**.
- DO(Distraction Optimization)를 앱이 선언하지 않았을 때 기본 동작:
  - Parking(주차): 사용 가능
  - Drive(주행): 사용 불가
  - Idling 행은 표에 없음. 주행 상황 분류(Parking, Idling, Driving)가 어떤 신호로 정해지는지는 **문서에 없음**.
- DO 선언 방법과 선언 시 동작 변화: **문서에 없음**.
- 표 범례: ✅ 사용 가능, ⛔ 사용 제한, `음성한정` 음성으로만 사용 가능. 「검색」은 웹 검색이 아니라 차량 내 통합 검색.

Parking 상태는 세 지역 모두 9개 기능 전부 ✅.

Driving 상태 (표 열 순서: 키보드 / 다이얼패드 / 검색 / 미디어 앱 로그인·설정·검색 / 디지털키·도어·시트·차량 설정 / 동영상 시청 / 내비게이션 검색 / QR 로그인 / 매뉴얼(대용량 텍스트)):

| 지역 | 키보드 | 다이얼패드 | 검색 | 미디어 로그인·설정·검색 | 디지털키·도어·시트·차량설정 | 동영상 시청 | 내비 검색 | QR 로그인 | 매뉴얼 |
|---|---|---|---|---|---|---|---|---|---|
| 북미 | ⛔ | ⛔ | 음성한정 | ⛔ | ⛔ | ⛔ | ⛔ | ⛔ | ⛔ |
| 유럽 | ✅ | ✅ | ✅ | ⛔ | ⛔ | ⛔ | ✅ | ⛔ | ⛔ |
| 그외 | ✅ | ✅ | ✅ | ✅ | ⛔ | ⛔ | ✅ | ⛔ | ⛔ |

- 원문 플래그 (참고용, 열 대응은 평탄화로 불명확): 키보드 = UX_RESTRICTIONS_NO_KEYBOARD(8), 다이얼패드 = UX_RESTRICTIONS_NO_DIALPAD(1), 동영상 시청 = UX_RESTRICTIONS_NO_VIDEO(16), 매뉴얼(대용량 텍스트) = UX_RESTRICTIONS_LIMIT_CONTENT(32) + UX_RESTRICTIONS_LIMIT_STRING_LENGTH(4). 나머지는 NO_FILTERING(2), NO_SETUP(64)이 섞여 있음.
- 인포테인먼트 "키보드 정책"은 지역별 분기 대상이다. InfoLINK용 앱은 지역별 키보드 분기가 필요할 수 있고, 자세한 사항은 partnership@pleos.ai 문의.
- 주행 규제 상태의 미디어 재생 제한·입력 처리 원칙은 "주행 안전을 고려한 설계"를 참고하라고 한다.

## 2. 주행 안전을 고려한 설계 / 주의 분산 가이드라인 (driver-distraction-guideline.md)
- AAOS 운전자 주의 분산 가이드라인(source.android.com 링크)을 준수한다고 명시.
- 사용 가능 여부와 기능 제한은 주행 상태, 지역, 앱 카테고리에 따라 달라진다.
- 앱은 `CarUxRestrictions`를 기준으로 제한 상태를 확인하고, 제한 대상 기능의 UI·동작을 축소하거나 비활성화해야 한다.
- **주행 규제 상태에서 영상 재생을 시작하거나 재개하지 않도록** 처리해야 한다.
- 오디오 재생은 오디오 포커스 개발 가이드 정책을 따른다.
- 시선 분산 최소화:
  - 운전에 필요한 정보는 짧은 시간 안에 이해할 수 있도록 간결·명확하게 표시한다.
  - 주행 중 시선을 과도하게 끄는 동영상, 애니메이션, 움직이는 이미지를 최소화하거나 제한한다.
  - 이미지는 정보 전달에 필요한 범위에서 최소한으로 쓰고, 장식적·반복 움직임 요소는 지양한다.
- 정보 구조·인터랙션:
  - 필요한 기능에 최소한의 조작으로 도달하도록 화면·메뉴 구조를 단순화한다.
  - 자주 쓰는 기능은 첫 화면·상단에 둔다. 드롭다운·다단 메뉴는 남용하지 않는다.
  - 주행 중 자동 애니메이션·반복적 화면 전환을 최소화한다.
  - 운전 관련 오디오 안내 시 오디오 포커스 정책에 따라 미디어를 일시 정지하거나 볼륨을 조정한다.
- 터치 조작:
  - Pleos Connect UI Design Guide의 large touch target, high contrast, 텍스트 최소화 패턴을 적용한다.
  - 터치 조작을 최소화하고 음성 명령·물리 버튼 등과 연계한다.
  - 게임, 인터넷 서핑, 피트니스 등 주의를 분산시킬 활동을 유도하지 않는다.
  - 버튼 크기·간격 기준은 UI Design Guide를 따른다 (구체 수치는 **이 문서에 없음**).
- 텍스트 입력 최소화: 검색·로그인에서도 키보드 입력보다 프리셋 선택, 최근 항목, 음성 입력을 우선한다.
- **글자 수, 터치 횟수, 시선 시간 등 수치 기준: 문서에 없음.**

## 3. 앱 카테고리 (app-category.md)
- 설계 시점부터 앱 카테고리를 명확히 정의해야 한다.
- 카테고리 목록 (문서는 "등"으로 끝나 목록이 완전하지 않을 수 있음):
  - Maps/Navigation: 위치 기반 길 안내
  - Mobility Services: 이동 수단·이동 서비스 제공
  - Lifestyle: 일상생활 관리·향상
  - Entertainment: 오락·여가
  - Business: 업무·생산성 지원
  - Music/Audio: 오디오 콘텐츠 중심
  - Kids: 아동 대상 콘텐츠
  - Social/Communication: 사람 간 소통·네트워크
- 카테고리와 주행 상태에 따라 주행 중 기능 범위가 달라진다. 구체 기준은 지역별 정책 문서를 본다.
- 주행 중 제한적 허용 예시 (카테고리별, 예시이며 실제 적용은 주행 상태·지역 정책에 따름):
  - Music/Audio: 앨범 아트 등 단순 시각 정보, 재생/일시정지/곡 넘기기, 음악 스트리밍 청취, 라디오 채널 변경, 오디오북 재생.
  - Maps/Navigation: 경로 안내·실시간 교통, 주의를 분산시키지 않는 간결한 지도, TBT 음성 안내, 목적지 경로 탐색, 실시간 빠른 길 안내, 주변 교통 상황 안내.
  - Mobility Services: 주행과 밀접한 차량 관리 서비스, 현재 위치 기반 즉각 정보, 전기차 충전소 찾기·경유지 설정, 가까운 주유소 탐색, 주행 중 접근 가능한 주차장 위치 확인.
- **Business 카테고리의 주행 중 허용·제한 규칙: 문서에 없음** (예시 목록 없음).
- Lifestyle, Entertainment, Kids, Social/Communication의 규칙도 문서에 없음.

## 4. 앱 구조 및 화면 모델 (app-structure-screen-model.md)
- Driving view(운전자 가까운 고정 영역)와 앱 영역을 함께 표시하는 멀티 윈도우 환경이다.
- Driving view는 앱이 임의로 가리거나 종료할 수 없다.
- 앱 영역은 차량·디스플레이 구성에 따라 window 1개 또는 2개로 나뉜다.
- 표시 형태:
  - `portrait`: window 1개 사용. 앱 2개를 동시에 표시하면 각 앱은 보통 portrait.
  - `landscape`: 앱 1개가 두 앱 영역을 확장해 사용.
  - portrait와 landscape를 각각 설계해야 한다. portrait는 핵심 기능·주요 정보, landscape는 부가 정보·확장 기능.
- `screenOrientation` 미지정 시 Activity는 portrait, window 1개. `landscape` 지정 시 window 2개 사용 가능.
- 화면 방향은 `AndroidManifest.xml`의 `screenOrientation` 설정 기준이므로 화면 설계와 함께 검토한다.
- 새 앱은 현재 표시 중인 앱의 화면 방향을 기준으로 뜬다. landscape 앱 표시 중이면 새 앱도 landscape, portrait 2개 표시 중이면 새 앱은 primary window에 portrait.
- 화면에서 사라진 앱은 종료되지 않고 백그라운드에 남을 수 있다. 표시 중인 앱이 종료되면 최근 사용 순으로 다시 window에 뜰 수 있으므로 foreground 재진입을 고려한다.
- 사용자가 window bar·제스처로 위치·크기를 바꿀 수 있으므로 window 크기가 변해도 핵심 기능이 동작해야 한다. 반응형 레이아웃 사용.
- 화면 픽셀 크기·해상도 수치: **문서에 없음**.
- 포그라운드·백그라운드 설계:
  - 포그라운드 진입 시 상태 복원, 화면 크기·방향에 맞춰 UI 재구성.
  - 백그라운드 전환 시 화면 갱신, 애니메이션, 불필요한 센서 수집 등 중단 가능한 작업 정리.
  - 오디오 재생·통신·다운로드 등 백그라운드 지속 작업은 실행 조건과 중단·재개 정책을 명확히 정의.
  - 백그라운드에서 불필요한 상주, 타이머, 폴링, 네트워크 요청을 최소화.
  - 앱 종료·프로세스 재생성 시에도 사용자 데이터와 진행 상태를 복원할 수 있도록 상태 저장 전략 마련.

## 5. 성능 및 리소스 (performance-resource-mgmt.md)
- 여러 앱이 동시에 동작하므로 리소스 사용을 절제해야 한다. 빠른 기동, 가벼운 상주를 전제로 설계.
- 시작 시간: cold start 시 스플래시에 오래 머물지 않도록 최소 초기화. 초기 로딩은 필요한 것만, 나머지는 지연 로딩.
- CPU 사용률 기준:
  - 내비게이션 앱 (주행 중): **15% 이하**
  - 내비게이션 아닌 앱 (주행 중): **5% 미만**
  - 모든 앱 (정차 중): **25% 이하**
- RAM: **400 MB 이하** 유지.
- 백그라운드 긴 작업, 불필요한 타이머·폴링 최소화.
- 이미지·리스트는 리사이클 뷰, 캐시 전략으로 메모리 최적화.
- 배터리 수치: **문서에 없음**.
- 오디오·미디어 앱: Pleos Connect 오디오 포커스 정책을 준수하고, 포커스 획득·상실에 대응하는 로직을 **반드시 구현**해야 한다. 정책 상세는 별도 문서 참조 (우리 폴더에 없음).

## 6. 보안 및 개인정보 보호 (security-privacy.md)
- 차량은 여러 사람이 함께 쓰는 기기이므로 보안·개인정보에 유의한다.
- 상세 보안 기준은 "앱 보안 가이드" (App Market 등록 시 준수, 우리 폴더에 없음).
- 계정·세션:
  - 차량 소유자 변경, 운전자 교체 시 쉽게 로그아웃 및 계정 전환이 가능해야 한다.
  - 소셜 로그인, OTT 계정 등 토큰은 Keystore 등 안전한 스토리지에 저장.
- 개인정보 최소 수집:
  - 위치, 음성, 계정 정보 등을 요구할 때 "왜 필요한지" 명확히 하고, 동의 플로우는 간단하고 이해하기 쉽게.
  - 불필요한 개인정보(PII)는 **저장하지 않는다**.
  - 로그에 개인정보가 포함되면 마스킹하여 기록.
- 차량 외부로 나가는 데이터 (Telemetry/분석 이벤트):
  - 차량 ID, 사용자 ID의 익명화·가명화 정책을 수립.
  - 운전 중 행동 데이터를 마케팅 목적으로 쓰지 않도록 구분.
- 차량 내부 로컬 DB 저장 규칙, 암호화 요건, 보관 기간: **문서에 없음**.
- 외부 서버 통신 허용 여부 자체에 대한 규칙, 외부 전송 데이터의 종류 제한: **문서에 없음** (telemetry 익명화 규칙만 있음).

## 7. API 호환성 및 가용성 (api-compatibility-availability.md)
- 차량 모델마다 API 지원 여부가 다를 수 있으므로, 설계·개발 전에 SDK API와 AAOS vehicle property를 미리 확인한다.
- Pleos Connect SDK 호환성:
  - Vehicle SDK: 모델에 따라 다름. 도메인별 `checkXXXCapabilities` API로 가용 여부 확인.
  - NaviHelper SDK: 내비게이션이 탑재된 차량에 한해 전체 호환.
  - TextToSpeech SDK, SpeechToText SDK: 전체 호환.
  - FusedLocation SDK: 모델에 따라 다름. `isSupported` API로 확인.
- AAOS Vehicle Property:
  - 지원·접근 가능 여부는 차량 모델과 프로퍼티에 따라 다르다.
  - 정의·ID는 `VehiclePropertyIds`, 실제 차량의 설정·접근 가능 여부는 `CarPropertyManager`로 확인.
  - **차량 모델명을 기준으로 분기 처리하지 말고** `VehiclePropertyIds`와 `CarPropertyManager`로 실제 지원·접근 상태를 확인.
  - SDK가 제공하지 않는 특수 프로퍼티가 필요하면 직접 구현 전에 **기술 지원팀에 검토를 요청**.

## 8. 하드웨어 접근 정책 및 네트워크 (platform-api-architecture.md)
- 앱은 Pleos Connect SDK가 제공하는 표준 플랫폼 API로 하드웨어에 접근해야 한다.
- 차량 하드웨어 직접 접근 금지 (물리 제어·센서 직접 접근 불가). 차량 상태는 플랫폼 API로 확인·제어.
- 모바일 전용 API 제한 가능 영역: Telephony(전화), SMS, 일부 센서(자이로, 근접 등), 캘린더, 주소록.
- 대응: 차량 환경에 필수적이지 않은 기능은 제거하거나, API 지원을 확인한 뒤 동작하도록 Optional 구조로 설계.
- 주행 중 네트워크:
  - 셀룰러·Wi-Fi 연결이 끊기거나 대역폭이 급락하는 상황에 대비.
  - 권장: 최근 콘텐츠 로컬 캐싱, 요청 재시도(Retry)와 적절한 타임아웃, 네트워크 단절 시 오프라인 모드 안내 UI.
- 재시도 횟수·타임아웃 초 단위 수치: **문서에 없음**.

## 9. SDK API 정책 (pleos-connect-sdk-api.md)
- AAOS Alignment 정책:
  - 표준 우선: 동일·유사 기능이 AAOS 표준에 있으면 표준 API 사용을 권장하며 SDK는 중복 기능을 제공하지 않는다.
  - 확장: AAOS 표준으로 접근 불가하거나 제조사 고유 보안·특화 제어가 필요한 영역에 한해 SDK 전용 API 제공.
- 하위 호환: SDK 전용 기능이 AAOS 표준으로 편입되어도 기존 SDK API는 **최소 2개 메이저 버전**까지 하위 호환을 유지.
- API 선택 기준:
  - 표준 데이터 (AAOS Car API): 속도, 기어 상태, 외기 온도, 연료 레벨 등
  - 특화 기능 (Pleos Connect SDK): 제조사 전용 시트 제어, 특화 라이팅, 고유 보안 인증 등
- 차량 모델별 지원 API는 API 호환성 문서 참조.

## 우리 앱에 주는 영향

근거 파일은 원문 파일명(`.md`)으로 표기. 우리 앱 맥락: 백그라운드 운행 기록, P단에서만 운전자 선택·용무 입력, 직원 이름·위치 로컬 DB 저장, 국세청 양식 QR 전달(외부 서버).

### 1. 백그라운드 기록 (시동~시동 끔, 계기판 누적거리·목적지·연료량)
- **허용**: 백그라운드 지속 작업은 실행 조건·중단·재개 정책을 정의하면 된다 (`app-structure-screen-model.md`). 상주 자체를 금지하는 문구는 없음.
- **제약**: 불필요한 상주·타이머·폴링·네트워크 최소화 (`app-structure-screen-model.md`, `performance-resource-mgmt.md`). 주행 중 CPU 5% 미만(내비 아닌 앱), RAM 400 MB 이하 (`performance-resource-mgmt.md`).
- **제약**: 프로세스 재생성 시 진행 상태 복원 전략 필요 (`app-structure-screen-model.md`). 운행 중 종료되어도 기록이 날아가지 않도록 저장 설계가 필수.
- **위험**: 속도·기어는 AAOS Car API 표준 데이터로 명시됨 (`pleos-connect-sdk-api.md`). 계기판 누적거리, 연료량은 문서에 명시 없음 → 차종별 지원을 `checkXXXCapabilities`/`CarPropertyManager`로 확인 필요 (`api-compatibility-availability.md`). 모델명 분기 금지.
- **위험**: 시동 끔 판정 기준, 주행 상태 분류 기준은 **문서에 없음**.

### 2. P단 입력 (운전자 선택, 용무 확인 화면)
- **허용 (기본 규칙)**: DO 미선언 시 Parking에서 사용 가능, Drive에서 사용 불가 (`driving-restiction-policy.md`). P단 = Parking이라는 매핑은 원문에 명시되지 않았으므로 **확인 필요**.
- **제약 (주행 중 화면)**: "기록 중" 표시만 두는 방식은 시선 분산 최소화 원칙과 맞다. 자동 애니메이션·반복 화면 전환은 최소화 (`driver-distraction-guideline.md`).
- **위험 (텍스트 입력)**: 키보드는 지역별 차이가 크다. Driving 상태에서 북미 ⛔, 유럽·그외 ✅ (`driving-restiction-policy.md`). 북미 판매 시 주행 중 키보드 입력 불가. 용무 입력은 프리셋·최근 항목·음성 우선으로 설계 (`driver-distraction-guideline.md`).
- **위험 (DO 선언)**: DO 선언 여부와 선언 시 동작 변화는 **문서에 없음**. 주행 중 "기록 중" 표시가 "사용"으로 간주되는지도 **문서에 없음**. 주행 규제 개발 가이드 확인 필요.
- **위험 (카테고리)**: Business 카테고리 규칙 **문서에 없음**. 예외 허용 목록에 Business는 없음.

### 3. 직원 이름·위치 로컬 DB 저장
- **허용**: 로컬 저장 자체를 금지하는 문구는 없음. 로컬 DB 저장 규칙은 **문서에 없음**.
- **제약 (최소 수집)**: 위치·계정 정보 요구 시 "왜 필요한지" 명확히 하고 동의 플로우를 단순하게 (`security-privacy.md`). 위치는 업무 목적(법인 운행기록)과 연결해 설명 필요.
- **제약 (PII)**: 불필요한 PII는 저장 금지. 로그에는 마스킹 (`security-privacy.md`). 이름·위치 기록이 용무 목적에 필요한 최소 범위인지 재검토 필요.
- **제약 (운전자 교체)**: 운전자 교체 시 쉽게 로그아웃·계정 전환이 가능해야 함 (`security-privacy.md`). 운전자별 기록 분리·전환 설계 필요.
- **위험**: 위치 획득 자체는 FusedLocation SDK 모델별 지원 차이 (`api-compatibility-availability.md`), `isSupported`로 확인. 토큰이 있다면 Keystore 저장 (`security-privacy.md`). 암호화·보관 기간은 **문서에 없음**.

### 4. 외부 서버 QR 전달 (국세청 양식 엑셀 링크)
- **허용·확인 필요**: 외부 통신 자체를 금지하는 규칙은 **문서에 없음**. 원문은 telemetry 설계 시 익명화·가명화 정책을 세우라고만 한다 (`security-privacy.md`). QR 링크로 폰이 받는 방식이 차량 밖으로 데이터를 보내는 경우에 해당하는지는 **문서에 없음**.
- **제약**: 차량 ID·사용자 ID가 외부로 나가면 익명화·가명화 정책 필요 (`security-privacy.md`). 엑셀에 이름·위치가 포함되면 PII 최소화 원칙 적용.
- **제약 (네트워크)**: 주행 중 네트워크 단절·저대역폭 대비, 재시도·타임아웃, 오프라인 안내 UI 권장 (`platform-api-architecture.md`). QR 생성은 정차 중에 하는 것이 안전하다는 근거는 **문서에 없음**. 다만 주행 중 화면 조작 최소화 원칙은 적용됨 (`driver-distraction-guideline.md`).
- **위험**: 외부 전송 데이터 종류·보관 제한, 앱 보안 가이드 기준은 **문서에 없음** (App Market 등록 시 "앱 보안 가이드" 참조 필요).

### 공통 확인 필요 사항
- 주행 상태 분류 기준, DO 선언 방법, Business 카테고리 규칙, 로컬 DB 보안 요건, 외부 통신 허용 조건: 모두 **문서에 없음**. `CarUxRestrictions` 개발 가이드, 오디오 포커스 정책, 앱 보안 가이드, UI Design Guide, `partnership@pleos.ai` 문의로 확인 필요.
