## 잠정 선정: A. 업무 운행 자동 기록·정산

### 한 줄 소개 (초안)
"시동을 걸면 차가 직접 기록하고, 주차하며 '업무'라고 한마디 하면 월말 정산서와 운행기록부가 완성되는 차량 내장 운행일지"

### 이기는 포인트
1. **"폰으로는 왜 안 되나?"에 정면으로 답함**: 폰 앱은 GPS 추정, 배터리 소모, 백그라운드 권한, 아이폰 자동화 문제가 있음 → 차는 실제 계기판 거리로 항상 기록함 (실제 앱 개발자 진술이 근거)
2. **폰 앱이 따라 할 수 없는 기능**
   - 공용 법인차 **운전자 자동 식별** (시트 위치·프로필)
   - **EV 업무 에너지 비용** 자동 계산 (EvBattery 전비 × kWh)
   - NaviHelper 목적지로 **방문처 자동 채움** + 예상 통행료
3. **Gleo 연동**: "방금 운행 업무로 기록해줘" → App Schema 함수 3개(`LOG_TRIP_PURPOSE`, `GET_MONTHLY_SUMMARY`, `EXPORT_LOGBOOK`)
4. **안전 설계**: 주행 중엔 UI 없이 백그라운드로 기록하고, 입력은 주차(P단) 상태에서 원탭 또는 음성으로만 받음 → 주행 규제 정책에 정확히 맞음
5. **프라이버시 설계**: 개인 운행은 위치 없이 거리만 저장, 기록은 수정 이력이 남는 구조 (독일 Fahrtenbuch 수준)
6. **사업성**: 지불 주체가 분명함(회사 차량당 월 과금, 사업자 구독, 세무사 채널). 한국·독일·미국 공통 제도라 글로벌 확장 스토리가 성립함

### 리스크와 대응
| 리스크 | 대응 |
|---|---|
| "그냥 운행일지 앱 아니냐"는 인상 | PT 첫 장면에서 폰 앱의 한계 → 차량 데이터로 해결하는 대비를 보여줌 |
| 운전자 식별 정확도 | 1차 범위는 "주차 시 운전자 확인 원탭", 시트 기반 추정은 고도화 기능으로 제시 |
| STT·TTS·FusedLocation이 "준비 중" (콘솔 확인됨) | 핵심은 Odometer·NaviHelper(위치·목적지·즐겨찾기)로 구성하고, 음성은 Gleo Interface 또는 STT가 열리면 확장 |
| 기어·속도 API가 Vehicle State에 없음 | AAOS `CarPropertyManager`(`GEAR_SELECTION`, `PERF_VEHICLE_SPEED`)로 읽기 → 개발 첫날 에뮬레이터에서 확인 |
| 세법 요건의 정확성 | 기획서 인용 전에 법인세법 시행령과 국세청 서식 원문을 확인 |
